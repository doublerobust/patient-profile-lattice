Implemented
  Browser rejects direct model set_view subset/focus (including null) and highlight_events actions. The new propose_display_scope tool supplies intent, whole-request evidence, and an unchanged-schema nested action. A separate local UI shows that mapping and requires approval before execution. Approval executes only the captured action, never resumes the model conversation, and cannot authorize a later request.
  Whole-request deterministic grammar requires exact patient IDs or source filters; exact JSON commands support compound filters. Unknown free-form scope language requires clarification rather than a model interpretation. Recognized unsupported clinical predicates are refused. The gate does not rely on the system prompt or schema validation to prove natural-language grounding.
  Original executable argument validation and analysis proposal/confirmation implementation remain unchanged. Direct user-entered local commands retain their prior behavior. Read-only queries and ordinary non-selection display styling are not changed by this display gate.
  Approval is bound to request text, connection/configuration, dataset and state snapshot. Cancellation, editing, disconnect, Undo/Reset and local commands invalidate it. Approval-time validation rechecks the action.

Supported model display scope wording
  Show only patients SYN-001, SYN-002
  Display only SYN-001
  Focus on SYN-001
  Show all patients
  Highlight source IDs AE-001-1, AE-002-1
  Highlight grade 3 AE records
  Highlight exact term SYNTHETIC NAUSEA
  An exact JSON set_view/highlight_events command, with existing schemas.
  Evidence must equal the complete trimmed request. Action must exactly match the parsed request. The model cannot invent a different subset or add extra settings. This conservative grammar intentionally rejects otherwise reasonable paraphrases. Clinical keyword refusal is not a universal language classifier; unknown phrasing remains closed via the grammar.
