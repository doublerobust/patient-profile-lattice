Task t_82087039: spike contract and synthetic SDTM fixtures
Version 1.0.0

Purpose and boundary
  This is the golden contract/fixture handoff, not the downstream generator or UI.
  All records and clinical-documentation examples were invented for this task.
  They are SDTM-like feasibility inputs, not a conformant regulatory submission.
  No real patient or trial data is included. No external model or agent was spawned.

Files
  contract.json          Versioned normative machine-readable rules and acceptance cases.
  schemas.json           JSON Schema Draft 2020-12 definitions for normalized state,
                         source refs, relationship evidence and clarification responses.
  fixtures.json          Hand-authored AE, CM, EX, RS, RELREC, SUPPAE, roster,
                         synthetic relationship documentation and eight test requests.
  expected_results.json  Separately stated golden outputs; never generated by the checker.
  evidence.json          Original CDISC source, supporting excerpts, classifications,
                         severity, smallest corrections and explicit design choices.
  normalized_spec.json   Executable example state bound to actual snapshot/rule hashes.
  manifest.json          Fixed seed, snapshot ID, rule version and exact file SHA-256 pins.
  validate.py            Local reference harness, integrity checks and unittest cases.
  verification.txt       Real test transcript from the latest validation run.
  verification.json      Machine-readable latest validation result and limits.

Use
  From this directory, run:
    python3 validate.py
  Requires jsonschema with Draft 2020-12 support. No network access is required.
  If deliberately changing a versioned input, update versions/oracles as appropriate,
  then explicitly regenerate the example spec and manifest:
    python3 validate.py --seal
  The seal option does not generate or alter golden fixture records or expected results.
  A fixed seed is a downstream generator requirement, not a claim these inputs were
  produced by a random-number generator. Do not replace golden expectations with
  whatever a producer implementation happens to return.

Golden results
  F01_counts: 2 qualifying patients versus 3 SEVERE AE records, from 3 patients/7 AE rows.
  F02_group_endpoint: one logical relationship with an AE endpoint and a CMGRPID=G1
    endpoint resolving to both CM-001-1 and CM-001-2, never CM-002-1.
  F03_blank_reltype: association retained; RELTYPE remains the empty string; observed
    endpoint cardinality does not fill ONE/MANY or establish hierarchy.
  F04_undocumented_meaning: AE-002-1 associated with RS-002-1; clinical meaning and
    direction unknown with no semantics-document citation. Do not imply causality.
  F05_ambiguous_time: ask for temporal clarification; result and normalized analysis
    are null, not zero. The wording already specifies patients, not an unknown unit.
  F06_explicit_time: first complete EX start, AE onset, inclusive elapsed calendar days
    0 through 30; 3 qualifying patients/5 AE records. Day 31 excluded; partial date
    excluded with diagnostic. These are not inferred treatment-emergent events.
  F07_view_replay_picking: view sort/peel/focus/clip preserve the 2/3 analysis; stable
    AE-001-2 pick resolves original AE row 2. Analytical restriction to SYN-002 gives
    1 patient/1 AE and clears the old selection rather than retargeting it.
  F08_suppqual: SUPPAE-001-1 qualifies AE-001-1 without creating another AE.

Downstream implementation
  Read contract.json, schemas.json and expected_results.json before implementing.
  Preserve source raw values and original snapshot row numbers; screen row indexes
  are not record identities. RELREC logical endpoints may contain multiple records.
  SUPPQUAL is a model/category here; the concrete dataset is SUPPAE because a pooled
  SUPPQUAL submission was deprecated under the pinned SDTMIG 3.3 reference.
  V1 deliberately supports only subject-record RELREC associations and one explicit
  temporal mode. Unsupported dataset relationships retain raw rows and fail closed.
  Unknown/missing temporal parameters must not be silently normalized into defaults.
  Clinical documentation in fixtures is synthetic test input, not medical evidence.
  IDs in this small package use a collision-free fixed alphabet; future generalized
  identity encodings must avoid ambiguous delimiter concatenation.

Verification and independence
  verification.json and verification.txt contain the actual latest results; no static
  test count or timing in this README should substitute for those files.
  Expected results were stated separately from the checker, but the same GPT Sol
  session authored both. This is self-verification, NOT independent review.
  Reference-harness picking checks stable identity logic, not pixels in a renderer.
  Actual UI, Antigravity and generator execution belong to dependent cards and were
  not run here. Full SDTM conformance, clinical validity and independent audit are
  not checked. The supplied task had no existing producer artifact to independently audit.
